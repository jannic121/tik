§01Why it exists

Purpose & vision

Live streams are ephemeral — they vanish when the creator ends them. This system's job is to monitor a watchlist of TikTok creators, record their live streams the instant they go live, and turn every recording into durable, searchable content: video safely archived, audio transcribed to timestamped text, and live chat captured alongside.

It is built for a single operator running a self-hosted fleet of cheap machines, driven entirely from one web interface. The machines are cattle, not pets. The three promises are simple: never miss a stream, never lose a recording, make the archive instantly searchable.

§02Who & what

Actors & roles

OperatorThe single human owner. Manages the watchlist, storage, and archive; reads transcripts.
Control planeThe brain: source-of-truth database, orchestration of every transfer, and the web UI.
Recorder backendA machine that watches assigned creators and records their streams.
Storage / transcriptionA machine that stores video, transcribes with Whisper, and pushes to cloud.
Cloud archiveAn external object store (any rclone remote) holding the durable copy of the video.
CreatorA watched TikTok user — the subject of recording, not a system user.
§03End to end

The pipeline

Every recording moves through the same states, and the operator sees each one live, per recording:

recording on storage / archived transcript available searchable

When a creator goes live, the recorder captures the stream to a per-creator file. When it ends, the file is finalised and fans out into two independent paths: the video is moved to durable storage (a storage box and/or the cloud, always verified before the local copy is deleted), and the audio is transcribed and folded into a search index. If chat capture is on, comments, gifts, and likes are logged during the live and indexed too.

§04What it must do

Functional requirements

Eleven areas. Items marked target are intended direction, not yet built.

4.1Watchlist

Add / remove creators by username, per-creator poll interval and chat toggle, auto or manual backend assignment, and safe migration between backends that never records a creator twice.

4.2Recording

Fast lossless remux, recovery of interrupted recordings, and an absolute rule: a file still being written is never touched by anything downstream.

4.3Video durability & archive

Every recording reaches ≥1 verified durable location before its local copy can be dropped. Any rclone cloud, retention & disk-pressure eviction, and playback that works after the local copy is gone.

4.4Transcription

Timestamped transcripts via Whisper; salvage of corrupt/truncated recordings; optional audio-first mode so the full video bypasses the transcription box; on-demand re-transcription.

4.5Chat capture

Comments, gifts and likes logged during the live, matched to their recording and full-text indexed. One-click fix when dependencies are missing.

4.6Search & catalog

One fast, local full-text search across all transcripts and chat, with filters and snippets. The Files view is catalog-backed, not a per-keystroke fan-out.

4.7Playback & viewing

Transcript viewer and video player. target — synced playback: click a line to seek, the current line follows, search jumps the player.

4.8Cookies

Stored per backend, applied without restart, viewable at a glance across the fleet with set/missing status. target — detect likely-expired cookies and alert.

4.9Alerts

Proactive ops notifications — disk filling, box unreachable, watchers in error, transcription give-ups, archive failures — over webhook / ntfy / Slack. target — content notifications (“live now”, “transcript ready”).

4.10Fleet ops & deploy

One-click provision and update over SSH; update detection by build id; deploys robust to file ownership; machine identity is ssh_host:port, so NAT’d boxes and colocation are handled correctly.

4.11Cost & capacity target

One view of total stored, growth rate, days-to-full per box, and estimated monthly cloud cost per creator — so retention is a data-driven decision.

§05Always true

Cross-cutting invariants

Rules that override every optimisation. If a change would break one of these, the change is wrong.

No data lossA file is deleted from a location only after verified presence elsewhere. A smaller/truncated remote copy does not count.
No duplicate recordingA creator is recorded by exactly one backend at a time. Migrations preserve this or refuse.
No double transcriptionEach recording is transcribed once. Audio-first must not cause a box to also auto-transcribe the same video.
In-progress is sacrosanctNever transfer, transcribe, evict, or delete a file that is still being written.
Secrets never leakCookies, tokens and archive credentials never reach logs, transcripts, commit history, or plaintext config on a box.
Failures stay localOne bad file, box, or creator degrades only itself — never stalls or crashes the pipeline for the rest.
The UI can't be brickedA front-end error must not disable navigation or hide state. The operator always has a working way to see and fix the fleet.

§07Deliberately out of scope

Non-goals

✕

Not a multi-tenant SaaS. One operator, one trust boundary. Read-only viewer accounts are a possible future extension, not a core goal.

✕

Not an editing suite. Recording is a fast remux; clip-cutting and highlights are optional add-ons, not the core.

✕

Not a broader TikTok client. It does only what recording and chat capture require — no posting, interacting, or profile scraping.

✕

Not responsible for legality. The system provides the mechanism; how it’s used is the operator’s responsibility.

§09Terms

Glossary

Control plane
The orchestrating web app plus source-of-truth database.
Backend
A machine that records creators.
Storage box
A machine that stores video and/or transcribes.
Archive
The external cloud remote (rclone) holding durable video.
Catalog
The database of recordings, transcripts, chat, and locations.
Audio-first
Transcribing from a small extracted audio track, not the full video.
Salvage
Recovering a transcript from a corrupt or truncated recording.
Eviction
Deleting a local copy after it’s verified present on the remote.
Colocation
Recorder and storage roles running on one machine.
Machine identity
ssh_host:port — distinguishes boxes behind one NAT’d IP.
